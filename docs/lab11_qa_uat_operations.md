## 2. Тест пирамидасы және автоматтандыру

R3 нысанасы: 20 автотест. Үлес дөңгелектенбей, бүтін санмен бекітілген.

Бүгін автоматтанғаны: `tests/test_smoke_api.py` ішінде **11** pytest. Оның 10-ы unit/ереже, 1-і витрина файлын оқиды. Integration 0, E2E 0. Яғни бүгінгі автоматтандыру көлемі пирамиданың тек төменгі қабаты, 11 / 20 = **55%** жоспарлы жиынтықтан. Қалған 9 тест R2 (себет PR-ы) және R3 (ҚР хосты) қақпасына байланған. Playwright бұл машинаға орнатылмайды, сценарийі UAT-10-мен бірдей болғанда ғана қосылады.

k6 пирамидаға кірмейді. Ол NFR жүктемесі, функционалдық регрессия емес.

## 9. SRE: бюджет, бақылау, кезек

SLO `lab08` бойынша. Айлық қате бюджеті 216 минут. Саясат:

1. Бір оқиға бюджеттің **10%-ынан** (21,6 минут) көп алса, жаңа скоуп тоқтатылады. Сенімділік жұмысы ғана қалады.
2. Төлем 5xx үлесі 5 минут бойы **> 5%** болса, төлем жолы жабылады, каталог ашық тұрады.
3. Бюджет ай соңында күймесе, келесі айдың жоспары US-11/US-12-ні ала алады. Күйсе, алмайды.

## 11. Runbook: төлем шлюзі

**Қашан ашылады.** Төлем жолының 5xx үлесі 5 минут бойы 5%-дан үлкен, немесе шлюз денсаулық тексеруі 3 рет қатарынан сәтсіз, немесе p95 5 минут бойы 800 мс-тен жоғары.

**Кезекші.** Сол аптаның QA. 15 минут ішінде жауап. 22:00–09:00 аралығы келесі таңға қалдырылады, scientific емес: дүкен жабық, түнгі сатылым жоқ.

### Диагностика

Staging мынамен көтеріледі:

```bash
docker compose -f docker-compose.monitoring.yml up -d
```

Содан кейін, хосттан:

```bash
curl -s -o NUL -w "%{http_code} %{time_total}\n" http://127.0.0.1:8080/
docker compose -f docker-compose.monitoring.yml ps
docker compose -f docker-compose.monitoring.yml logs --since 15m storefront
```

Қарау тізімі, ретімен:

1. Витрина коды 200 ме, уақыты 0,8 с-тен аз ба.
2. Kuma-да төлем мониторы қызыл ба, витрина ше.
3. Соңғы 15 минутта себет өзгерісі шыққан ба. Шықса, бұл жаттығудағы 10% фактор.
4. Логта телефон толық па, мекенжай бар ма. Бар болса, инцидент екінші контурға ашылады (NFR-08), PAN болса тоқтату дереу.

R3-ке дейін төлем URL-і жоқ. `curl` төлемге 404 немесе байланыс қатесін берсе, бұл «шлюз жауап бермеді» деп жазылады, витринаны өшіруге себеп емес.

### Қалпына келтіру

1. Төлем redirect-ін жабу. Каталог қалады.
2. Пайдаланушы мәтіні, қазақша: «Төлем уақытша қабылданбайды. Тапсырыс жазылмайды.»
3. Себет өзгерісі соңғы жасыл тегке қайтады. Витрина тегі тиілмейді, егер қате тек төлемде болса.
4. 5xx үлесі 5%-дан төмен түскенше redirect жабық.
5. Жабылу уақыты минутымен жазылады. MTTR = жабылу − 18:04 үлгісіндегі басы.

Дерек жойылмайды. Қайтару скрипті тапсырыс кестесін тазартпайды.
